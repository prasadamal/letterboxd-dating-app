# ReelMates — owner launch guide

Everything you have to do yourself, in order. Each step says **where**, **what to paste**, and **how to check it worked**.
The code, database schema and build configuration are already done; this guide is accounts, keys and buttons.

| Stage | Result | Time | Cost |
|---|---|---|---|
| 1. Run it on your phone | App working on your Android phone and iPhone via Expo Go | 30–45 min | Free |
| 2. Put the API online | Public HTTPS API + admin page | 20 min | Free (Render) |
| 3. Installable builds | Real Android APK; iPhone build via TestFlight | 1–2 h + Apple approval | Apple $99/yr |
| 4. Launch | Google Play + App Store listings | 1–3 weeks (store rules) | Google $25 once |
| Running costs at launch | Render Starter + Supabase Pro | — | ~$7 + $25 / month |

Values you will collect along the way (keep them in a password manager, never in git):

| Value | Where it comes from | Where it goes |
|---|---|---|
| Supabase **secret / service_role key** | Supabase → moviematch → Project Settings → API Keys | Your local `.env`, Render |
| `ADMIN_API_KEY`, `CRON_SECRET` | Generated by Render on first deploy | `/admin` login, GitHub secret |
| Render URL, e.g. `https://reelmates-api.onrender.com` | Render dashboard | `mobile/eas.json`, GitHub secret |
| Resend API key | resend.com → API Keys | Render |
| Firebase service-account JSON | Firebase console | `eas credentials` (Android push) |

> The Supabase URL and the **publishable** key are already filled in. The publishable key is meant to be public;
> the database refuses it for every table. The **secret** key is the dangerous one: only `.env` and Render.

## Stage 1 — Run it on your phones today (free)

The API runs on your computer, the app runs inside **Expo Go**. Works for Android and iPhone, no developer accounts.

### 1.1 Install tools (once)
- **Node.js 22 LTS** from nodejs.org, and **Git**.
- On your phone(s): **Expo Go** from Google Play / the App Store.
- Phone and computer on the **same Wi‑Fi**.

### 1.2 Get the code and the secret key
```bash
git clone https://github.com/prasadamal/letterboxd-dating-app.git
cd letterboxd-dating-app
npm install
cp .env.example .env
```
Open `.env` in an editor and change two lines:
```
SUPABASE_SERVICE_ROLE_KEY=<paste the secret / service_role key from Supabase → Project Settings → API Keys>
FORCE_DATING_OPEN=true
```
`FORCE_DATING_OPEN=true` opens the dating tabs for **your local API only**, so you can test matching without 1,000 sign-ups.
It does not change the shared database and is refused in production.

### 1.3 Start the API (and the web version)
```bash
npm run dev
```
This starts the API on port 4000 and the web app on http://localhost:3000.
In a second terminal, from the same folder:
```bash
npm run smoke
```
**Check:** four lines starting with `OK`. If `health` fails, the secret key is wrong or missing.
Windows: if Windows Firewall asks about Node.js, click **Allow** (private networks).

### 1.4 Start the mobile app
Third terminal:
```bash
cd mobile
npm install
npx expo start
```
Do **not** create `mobile/.env` for this — without it the app finds the API on your computer automatically.

- **Android:** open Expo Go → *Scan QR code* → scan the code in the terminal.
- **iPhone:** open the normal **Camera** app → point at the QR code → tap the banner.

If the phone can't connect (office/hotel Wi‑Fi blocks devices from seeing each other):
```bash
npx cloudflared tunnel --url http://localhost:4000      # prints https://something.trycloudflare.com
```
Create `mobile/.env` with `EXPO_PUBLIC_API_URL=https://something.trycloudflare.com/api`, then run `npx expo start --tunnel`.

Expected and harmless in Expo Go: a warning that remote push notifications need a development build.

### 1.5 What to test (you need two accounts: one man, one woman)
Use two phones, or one phone plus the web app at http://localhost:3000 (sign-up, taste cards and an older dashboard).
1. **Sign up** on both. Age must be 18+; pick **Dating too**, how you identify and the **same city**; tick the Terms box. Add a photo at
   the last step (or later in You → Edit profile). A third account with **Films & friends** should never appear in decks.
2. **Today:** swipe the 10 films (right = loved it, left = nah, up = haven't seen). Each swipe shows how everyone else
   voted; after the last one you get **Daily results** with a *Share my results* button.
3. **You:** after 8 ratings your **film personality** appears. Set an all-time favourite and prompts in Edit profile.
4. **Match:** open your city in `/admin` (or set the city target to 1). Each account should see the other (dating needs a
   name, photo and country). Like each other → *It's a match*.
5. **Chats:** each sends one hello (try a conversation starter) → full chat unlocks → send a few messages, see *Read*.
6. **Safety:** Report (pick a reason) and Block from the chat menu; the conversation should close.
7. **Reset password:** Log in → *Forgot password?* → enter the email. Without email configured, the reset link appears
   on screen in dev mode; open it in a browser.
8. **Explore:** search a film, rate it Like / Dislike / Haven't seen; switch collections in the People's chart.
9. **Here for:** You → Settings → switch to *Films & friends*: the Match tab disappears; switch back.
10. **Film friends** (You → Film friends): add the other account's code → compare → Watch together.
11. **Taste card:** You → *Share my taste card* → open the link in a browser (`/taste/<code>`).
12. **Send feedback** (Settings) → it appears in `/admin` → Feedback inbox.
13. **Offline:** turn Wi‑Fi off, reopen the app → *Can't reach ReelMates / Try again* (you stay signed in).
14. **Delete account** from Settings on one test account → it disappears from the other account's matches.

Anything that fails here: note the screen and the message, and send it to me — this is the first real end-to-end run.

## Stage 2 — Put the API online (Render, free to start)

### 2.1 Deploy with the Blueprint
1. Sign up at **render.com** with your GitHub account and allow access to `letterboxd-dating-app`.
2. Dashboard → **New** → **Blueprint** → choose the repo → it reads `render.yaml` and shows `reelmates-api`.
3. It asks for the values marked secret:
   - `SUPABASE_SERVICE_ROLE_KEY` → paste the secret key.
   - `RESEND_API_KEY`, `EMAIL_FROM`, `SENTRY_DSN` → leave empty for now.
4. **Apply**. The first build takes ~5 minutes.

`JWT_SECRET`, `JWT_REFRESH_SECRET`, `ADMIN_API_KEY` and `CRON_SECRET` are generated by Render automatically.

### 2.2 Check it
- Open `https://<your-service>.onrender.com/api/v1/health` → `"db":"up"`. The `setup` list shows what's still unconfigured (email until Stage 2.4).
- Or from your computer: `SMOKE_API_URL=https://<your-service>.onrender.com npm run smoke`.
- Render → your service → **Environment** → copy `ADMIN_API_KEY` and `CRON_SECRET` into your password manager.

Free instances sleep after ~15 minutes idle; the first request then takes about a minute. Fine for testing —
switch the plan to **Starter** (Render → Settings → Instance type) before real users arrive.

### 2.3 Admin page
Open `https://<your-service>.onrender.com/admin`, paste `ADMIN_API_KEY`, **Load queue**.
- **Launch gate:** current counts, change the 500/500 targets, or **Open dating now** (e.g. for store reviewers).
- **Reports:** Review / Resolve / Dismiss, and **Suspend reported user**. Check this at least once a day after launch —
  the Terms promise action within 24 hours.
- **Feedback inbox:** messages from *Send feedback* in the app (ideas, bugs, missing films). Mark read / done.

### 2.4 Email (password reset + verification) — Resend
1. Sign up at **resend.com** → **Domains** → add a domain you own (e.g. `reelmates.app`) → add the DNS records it shows at
   your domain registrar → wait for *Verified*.
   (No domain yet? Resend's test sender only delivers to your own address — fine for testing, not for users.)
2. **API Keys** → create a key with *Sending access*.
3. Render → Environment → set
   - `RESEND_API_KEY` = the key
   - `EMAIL_FROM` = `ReelMates <noreply@yourdomain.com>` (must be on the verified domain)
   → Save (Render redeploys).
4. **Check:** `/api/v1/health` shows `"email":"configured"`; request a password reset in the app and receive the email.
   The link opens `https://<your-service>.onrender.com/reset-password?...`, served by the same service.

### 2.5 Scheduled jobs (free, GitHub Actions)
GitHub → repo → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**, twice:
- `REELMATES_API_URL` = `https://<your-service>.onrender.com` (no trailing slash, no `/api`)
- `REELMATES_CRON_SECRET` = the `CRON_SECRET` from Render

**Check:** GitHub → **Actions** → *Scheduled jobs* → **Run workflow** → it should finish green.
It then runs daily (game reminder push) and weekly (pauses long-inactive profiles). GitHub disables schedules in repos with
no commits for 60 days — re-enable from the Actions tab if that happens.

## Stage 3 — Installable builds

### 3.1 Expo account and project (once)
```bash
npm install -g eas-cli
cd mobile
eas login            # create the account at expo.dev if you don't have one
eas init             # creates the project and writes "owner" + "extra.eas.projectId" into app.json
```
Commit the `app.json` change and push it.

### 3.2 Point the builds at your API
Edit `mobile/eas.json`: replace both `https://YOUR_PRODUCTION_API_HOST/api` (in `preview` and `production`) with
`https://<your-service>.onrender.com/api`. Commit and push.
Builds without a real URL refuse to start and show "This build has no server configured".

### 3.3 Android test build (no Google account needed)
```bash
eas build -p android --profile preview
```
~15 minutes. Open the link it prints **on your Android phone** → download the APK → allow installs from your browser → install.

### 3.4 iPhone builds (needs the Apple Developer Program)
1. Enroll at **developer.apple.com/programs** ($99/year; approval can take 1–2 days).
2. Pick one:
   - **Direct install (ad hoc):** `eas device:create` → open the link on your iPhone to register it →
     `eas build -p ios --profile preview` → open the build link on the iPhone → install.
     (iOS 16+: Settings → Privacy & Security → Developer Mode → On, then restart.)
   - **TestFlight (also how you'll invite testers):** `eas build -p ios --profile production` →
     `eas submit -p ios --latest` → App Store Connect → TestFlight → add yourself as a tester.

No Apple account yet: keep using Expo Go (Stage 1), or on a Mac run `eas build -p ios --profile simulator` for the iOS Simulator.

### 3.5 Push notifications (new match, new message, daily reminder)
- **iOS:** EAS creates the Apple push key during the first iOS build when you're signed into your Apple account — say yes.
- **Android:**
  1. **console.firebase.google.com** → Add project → add an **Android app** with package name `com.reelmates.app`.
  2. Project settings → **Service accounts** → **Generate new private key** (downloads a JSON — keep it private).
  3. `cd mobile && eas credentials` → Android → production → **Google Service Account** →
     *Manage your Google Service Account Key for Push Notifications (FCM V1)* → upload the JSON.
- Rebuild after this. **Check:** match with a test account on another phone → you get a notification.

Once the Expo project exists and the GitHub repo is linked to it (expo.dev → project → GitHub), I can start builds for you.

## Stage 4 — Launch

### 4.1 Production data and hosting (before any real user)
1. **Supabase → Billing → upgrade to Pro** ($25/month). Free projects pause after a week without traffic and have no daily backups.
2. **Render → instance type Starter** ($7/month) so the API doesn't sleep.
3. **Clean the database** (removes the demo accounts — their password used to be public — plus your test accounts, and closes the gate):
   ```bash
   npm run db:prelaunch-cleanup                                        # dry run: shows what it will delete
   npm run db:prelaunch-cleanup -- --yes --emails you+a@x.com,you+b@x.com
   ```
   Run it from your computer with the secret key in `.env`. Set `FORCE_DATING_OPEN=false` (or remove it) afterwards.
4. **Film catalog:** 1,044 films (608 of them Indian, in ten languages). The API adds missing films to the database
   when it starts, so deploying is enough. Popularity values for the added films are my estimates
   (`server/data/curatedFilmsMeta.js`, `server/data/indianFilms.js`) and drive the rarity bonus in matching; skim and
   correct any that look off. New films go at the end of `indianFilms.js` (never reorder: ids follow the list).
5. **Decide the city launch.** Dating opens in a city at 150 women + 150 men who switch it on. In `/admin` you can
   change that number, open a launch city by hand (e.g. Kochi and Thiruvananthapuram for IFFK), and see every city's
   progress. The public board at `/cities` is the "unlock your city" campaign page.
6. **Legal and support pages** live on the website: `/privacy`, `/terms`, `/support`, `/delete-account`. Set
   `VITE_SUPPORT_EMAIL` (and later `VITE_PLAY_URL`, `VITE_APP_STORE_URL`) on Render to an inbox you read; reviewers write
   there. The privacy policy names that address as the grievance contact required by India's DPDP Rules.

### 4.2 Google Play
1. **play.google.com/console** → create a developer account ($25 once; identity verification can take days).
2. **Create app** → name *ReelMates*, app, free.
3. **Testing first:** new *personal* developer accounts must run a **closed test with at least 12 testers for 14 days**
   before production is unlocked (check the current rule shown in Play Console). Start this early:
   `eas build -p android --profile production` → `eas submit -p android --latest` (track `internal`; see the service
   account note below) → promote to a closed test → invite testers by email.
4. **App content** (left menu), using the files in this repo:
   - Privacy policy URL: `https://<your site>/privacy`
   - Data safety: answers in `docs/store/google-play/data-safety.md`
   - Account deletion URL: `https://<your site>/delete-account` (deletion is also in the app: You → Settings)
   - Target audience: 18+ only, and switch on **Restrict minor access** (required for dating features) ·
     Content rating questionnaire: social app with optional dating, user-generated content and chat
   - App access: give reviewers a test login and a note that dating opens city by city (open everywhere in `/admin`
     while they review, then close it)
   - Ads: none
5. **Store listing:** copy from `docs/store/google-play/listing.md`; icon 512×512 from `mobile/assets/icon.png`;
   feature graphic `docs/store/assets/feature-graphic.png`; 4–8 phone screenshots from a real build.
   Recruit about 20 testers once (a Google Group works) and reuse them for every app you publish.
6. Automated submit needs a Play service account: Play Console → Setup → API access → create the service account,
   save the JSON as `mobile/store/google-play-service-account.json` (git-ignored). Otherwise upload the `.aab` by hand.

### 4.3 App Store
1. **App Store Connect** → My Apps → **+** → New app → iOS, name *ReelMates*, bundle ID `com.reelmates.app`, SKU `reelmates`.
2. Copy the numeric **Apple ID** of the app and your **Team ID**, and fill `submit.production.ios` in `mobile/eas.json`
   (`appleId` = your Apple account email, `ascAppId`, `appleTeamId`).
3. **App Privacy:** declare email, name, photos, user content (messages), identifiers (push token), usage data; all linked
   to the user, none used for tracking — matches `docs/legal/PRIVACY_POLICY.md`. Privacy policy URL:
   `https://<your site>/privacy`; support URL: `https://<your site>/support`.
4. **Age rating:** 17+ (frequent/intense mature themes not required; select user-generated content / unrestricted web is *No*).
5. **App Review Information:** a working test login and this note: *"ReelMates is a film app; dating is optional and opens city
   by city once enough people join. Dating is open for review so you can see matching and chat.
   Report/block: dating card and chat menu; account deletion: You → Settings → Delete account."* — use *Open everywhere*
   in `/admin` before submitting and close it after approval.
6. Listing copy: `docs/store/app-store/listing.md`; screenshots for 6.7" and 6.5" iPhones.
7. `eas build -p ios --profile production` → `eas submit -p ios --latest` → TestFlight with your testers → select the
   build in App Store Connect → **Submit for Review**.
8. **Release gradually:** a staged rollout on Play (10% → 50% → 100%) and the 7-day phased release on iOS, so a crash
   reaches a few people first.

Sign in with Apple is not required: the app only offers email/password sign-in.

### 4.4 After launch
- Check `/admin` reports daily; suspend abusive accounts.
- Watch Render logs and `/api/v1/health`. Optional: create a Sentry project and set `SENTRY_DSN` on Render for error alerts.
- New app versions: bump `version` in `mobile/app.json`, then build + submit again (build numbers increment automatically).
- Have the Terms and Privacy Policy reviewed for the countries you launch in (GDPR if EU/UK users).

## Troubleshooting

| Symptom | Fix |
|---|---|
| `Invalid environment configuration` on start | A value in `.env` is malformed; the message names it. Empty values are fine. |
| `npm run smoke` → `health` fails | Wrong/missing `SUPABASE_SERVICE_ROLE_KEY`, or the API isn't running. |
| Phone: "No connection" | Same Wi‑Fi? Firewall allowed? Otherwise use the cloudflared tunnel (Stage 1.4). |
| Dating tab missing | Locally: `FORCE_DATING_OPEN=true` and restart `npm run dev`. Online: open the member's city (or everywhere) in `/admin`, or lower the city target. |
| "Add your city" on the Match tab | Dating opens city by city: set a city in Settings → Dating preferences. |
| "Complete your profile before matchmaking" | Add a photo and country (80%). |
| Build app says "no server configured" | Replace `YOUR_PRODUCTION_API_HOST` in `mobile/eas.json` and rebuild. |
| Reset email never arrives | `/api/v1/health` must show `"email":"configured"`; `EMAIL_FROM` must use the Resend-verified domain. |
| Render first request very slow | Free instance waking up; switch to Starter. |
| iPhone won't open the ad hoc build | Device registered with `eas device:create` before the build? Developer Mode on? |
