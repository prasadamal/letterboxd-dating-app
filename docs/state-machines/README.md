# Reelmates state-machine inventory

Reviewed source baseline: upstream release-hardening PR #21 at `6319d7d5499905bad9380a2d8f0dd3e944656796` (not just main). Inventory covers the active mobile client, web client, API, jobs and database. States below are conceptual names where the code currently uses flags or timestamps; they are not new API enums.

Decision: use small typed transitions for coupled state, preserve server authority and persisted formats, and keep independent input/toggle state simple. Do not add a state-machine framework or rewrite all flows at once. No change can guarantee UX, DX and AX improve in every future circumstance; transition contracts and regression checks make that goal reviewable.

## Verification and future changes

- Toolchain: CI pins npm 11.9.0, also declared in root/mobile packageManager. A fresh npm 11 install succeeds with the existing lockfile; the runner's default npm 10 rejects its optional peer graph. Native dependency versions and lockfiles are unchanged by this patch.
- `node scripts/state-index.mjs --check` validates the reproducible source evidence index. Run without `--check` after code changes, then review new candidates.
- `npm test && npm run build`; in `mobile`: `npm test && npm run typecheck && npm run lint`.
- The chat contract test exercises `/api` and `/api/v1`, intro/waiting/open and blocked conversations. Mobile transition tests cover allowed actions and missing/contradictory flags.
- Real-device chat flow: two test accounts, first hello, waiting state, reciprocal hello, send while polling, transient outage/retry, block, navigate between peers and switch accounts. Re-run Android/iOS exports and staging acceptance before release.

The evidence index includes hook state, timers, schema constraints and lifecycle fields, with file and line references. It is a broad source census, not a proof that every possible runtime machine has been discovered. The inventory groups simple independent state and repeated request lifecycles instead of inventing a machine per text input. Existing production launch blockers remain; this change does not apply migrations or deploy.
